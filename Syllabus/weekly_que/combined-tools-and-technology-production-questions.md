# Tools And Technology Production Question Bank

FAANG-level, Principal/Staff-scenario questions generated from `combined-tools-and-technology-reference.md`. Each topic's questions are grounded only in that topic's own tools and coverage. No answers included by design.

## Topic 1: Source Control And Collaboration

1. A `git rebase -i` performed on a shared feature branch rewrites history that three other engineers had already pulled, and their next push fails with a non-fast-forward error — how do you recover without forcing a push that discards their work?
2. A production hotfix commit was signed, but a downstream audit tool reports the signature as invalid even though the commit content matches the original — what would you check to explain this discrepancy?
3. A `git bisect` session to find a regression across 200 commits keeps landing on commits that don't build due to a broken intermediate state introduced by squash-merging — how do you make bisect reliable again for this repository going forward?
4. Branch protection on `main` requires passing status checks, but a required check silently stopped reporting status after a CI runner migration, and PRs have been merging without ever actually running it for two weeks — how do you detect this kind of silent gate failure?
5. A repository's `.git` history has grown to the point where clone times are impacting new-engineer onboarding and CI checkout time — what would you actually investigate before deciding whether history rewriting or a different strategy is warranted?
6. Code owners are configured to require review from a specific team on a critical path, but a merge commit bypasses this because the PR was merged via a fast-forward from a branch that never triggered the code-owners check — how do you close this enforcement gap?
7. A secret was committed and later removed in a follow-up commit, and secret scanning only flags new commits going forward — how do you determine whether the secret is still exploitable and what your remediation should include beyond rotation?
8. A release branching strategy allows hotfixes to be cherry-picked forward into main, but a cherry-pick silently drops a dependent change from the original commit, causing a subtle bug only in the hotfix branch — how do you catch this class of partial cherry-pick error?
9. Your organization's GitHub Enterprise instance goes down during a critical deployment window, and CI/CD pipelines that pull from it start failing — what fallback do you need in place to keep an emergency deploy possible?
10. A `git reflog` is used to recover a branch that was force-pushed over accidentally, but the reflog entry has already expired due to garbage collection — what would you have needed in place to make this recoverable?
11. Semantic-versioning automation bumps a package's minor version based on commit messages, but a commit incorrectly tagged as `fix:` actually introduced a breaking API change, and downstream consumers break on upgrade — how do you prevent commit-message misclassification from causing this?
12. A merge conflict resolution during a release freeze silently reintroduces a bug that had already been fixed on the target branch, because the conflict was resolved by favoring the wrong side — how do you build a review process that would catch this?
13. Webhook delivery from your Git hosting provider to a downstream deployment system silently stops working after a TLS certificate rotation on the receiving end, and nobody notices for a week because deployments still happen through a manual fallback — how do you detect this kind of silent integration failure?
14. Automated release notes generated from Conventional Commits omit a change that was committed with a malformed commit-type prefix, and customers don't learn about a behavior change until they hit it in production — how do you validate commit-message compliance before it affects release notes?
15. A repository backup exists, but a restore drill reveals the backup doesn't include Git hooks or branch protection configuration, only the raw repository data — how do you scope backups to actually support a full recovery?
16. A large monorepo's CI pipeline runs the full test suite on every PR regardless of which files changed, and a single unrelated documentation change now takes 40 minutes to merge — how do you use the repository's structure to fix this without reducing test coverage where it matters?
17. Two teams' pull requests both pass status checks independently, but merging them in sequence introduces a conflict-free but logically incompatible change that isn't caught until a production incident — how do you build a validation process that would catch semantic conflicts like this?
18. An approval requirement on a critical repository allows self-approval by repository admins, and an admin merges their own unreviewed change during an incident, which then causes a second incident — how do you design approval policy to prevent this without slowing down genuine emergencies?
19. A GitHub/GitLab runner used for CI has broader repository permissions than the pipeline actually needs, and a compromised dependency in a build step is able to push a malicious commit directly to a protected branch — how do you scope runner permissions to prevent this?
20. A version-compatibility issue arises because a dependency consumer pinned to a specific minor version range, but a release that should have been a major bump (due to a breaking change) was tagged as minor — how do you build validation that catches version-bump misclassification before publishing?

5. An Argo Rollouts canary analysis uses a metric provider that has a five-minute reporting delay, and the canary is promoted to 100% before the delayed metrics reveal a regression — how do you redesign the analysis template to account for metric latency?
6. A matrix build across multiple OS and dependency versions passes for all combinations except one, and the pipeline is configured to still report overall success because that combination isn't marked as required — how do you catch this kind of silently-accepted partial failure?
7. A Spinnaker multi-environment promotion pipeline deploys the same artifact to staging and production, but a manual approval gate between them was bypassed because of a pipeline configuration change nobody reviewed — how do you audit for this kind of gate bypass?
8. Self-hosted CI runners for CircleCI/Buildkite share a persistent workspace between jobs, and a previous job's leftover state causes a subsequent, unrelated job to pass tests it shouldn't have passed — how do you design workspace isolation to prevent this?
9. A blue-green deployment via Argo Rollouts completes the traffic switch, but the old "blue" environment isn't torn down due to an abort-handling bug, and it silently continues consuming production database connections — how do you catch this kind of incomplete rollback state?
10. A Jenkins plugin used for artifact publishing has a known vulnerability, but upgrading it breaks compatibility with three other plugins your pipelines depend on — how do you manage this risk without indefinitely deferring the security fix?
11. Reusable GitHub Actions workflow templates are used organization-wide, but a change to one template's secret-handling logic accidentally logs a secret value in a downstream consumer's build output — how do you build validation that catches this before it reaches every pipeline using the template?
12. A CI pipeline's retry logic automatically retries failed deployment steps, but a failure caused by a partially-applied database migration gets retried and applies the migration twice — how do you design retry logic that's safe for non-idempotent steps?
13. Artifact retention policy on your CI platform purges build artifacts after 30 days, but a production incident six weeks later needs the exact artifact from a specific historical deploy to reproduce a bug — how do you decide what retention policy actually serves incident response needs?
14. A queue-starvation issue on a Jenkins controller means high-priority hotfix pipelines wait behind dozens of low-priority scheduled jobs during an active incident — how do you redesign queue prioritization to prevent this?
15. Progressive delivery ownership for an Argo Rollouts canary is unclear during an incident, and the canary auto-promotes to 100% while the on-call engineer is still investigating a metric anomaly — how do you build clearer ownership and control into the promotion gate?
16. A provider outage for your hosted CI platform (CircleCI/Buildkite) blocks all deployments during a critical incident that requires an urgent hotfix — what fallback deployment path do you need to have validated in advance?
17. Pipeline permissions for a GitLab CI job are scoped broadly enough that a compromised dependency in one job's build step can read secrets meant for an entirely unrelated job's environment — how do you scope permissions to prevent this kind of lateral access?
18. A Spinnaker pipeline's artifact provenance isn't validated before deployment, and an artifact from an unexpected build source is deployed to production during a migration between CI systems — how do you enforce provenance validation during a transitional period like this?
19. Build isolation on a Jenkins agent is insufficient, and two jobs running concurrently on the same agent interfere with each other's dependency caches, producing an intermittent, hard-to-reproduce test failure — how do you diagnose and fix this class of flaky failure?
20. A canary analysis template for Argo Rollouts defines success purely by error rate, and a canary with a severe latency regression but normal error rate gets promoted to 100% — how do you redesign the analysis template to catch this?

15. An Ansible Vault-encrypted variables file is committed with the wrong vault password reference, and a subsequent playbook run silently uses stale, unencrypted fallback values instead of failing loudly — how do you design vault integration to fail safely rather than silently?
16. A Terragrunt environment-inheritance pattern means a change to a shared parent configuration unexpectedly propagates to a production environment during what was intended as a dev-only change — how do you scope inheritance to prevent unintended cross-environment propagation?
17. A Chef cookbook's idempotency assumption breaks after an upstream package's install script changes behavior, and repeated convergence runs cause a service to restart on every run instead of only when actually needed — how do you detect this kind of idempotency regression?
18. A Terraform `import` of existing infrastructure into state succeeds, but a subsequent plan shows a large diff because several resource attributes weren't captured correctly during import, risking an unintended change on the next apply — how do you validate an import before trusting it enough to apply against it?
19. A Pulumi component resource used across multiple stacks has a testing gap where unit tests validate the resource in isolation but never catch an interaction bug that only appears when composed with a specific other resource — how do you build testing that would catch this class of composition bug?
20. A rollback of a Terraform-managed change is attempted by reverting the code and reapplying, but the previous state no longer matches because a data source's underlying value changed since the original apply, producing a different result than expected — what are the actual limits of "rollback" for declarative infrastructure, and how do you plan around them?
21. An Ansible privilege-escalation configuration grants broader sudo access than a playbook actually needs for a specific task, and a compromised dependency in that playbook's role is able to make unrelated privileged changes — how do you scope privilege escalation more tightly?
22. A Terraform CI/CD pipeline auto-applies plans that pass policy checks without human review for a specific class of "safe" changes, but a change classified as safe turns out to have a scaling side effect that wasn't caught by policy — how do you define the boundary of what's safe to auto-apply?

## Topic 4: Containers And Image Supply Chain

1. A multi-stage Docker build accidentally copies a build-time secret into the final image layer, and it isn't caught until an SBOM scan on the already-published image flags it — how do you prevent secrets from leaking into final image layers in the first place?

4. A container image passes vulnerability scanning at build time, but a newly disclosed CVE in a base-image dependency means every already-deployed instance is now vulnerable, and there's no process to re-scan running workloads — how do you close this gap?
5. A rootless Docker container still manages to write to a host-mounted volume with root-equivalent effective permissions due to a UID mapping misconfiguration — how do you validate that rootless execution is actually providing the isolation you assume?
6. An SBOM generated at build time lists a transitive dependency's license as permissive, but a later, more thorough audit finds the actual license terms create a compliance conflict for your product — how do you catch license issues that automated SBOM generation might miss?
7. A container registry's retention policy garbage-collects an image digest that a canary rollback plan depended on, and the rollback fails because the known-good image no longer exists — how do you design retention policy to protect rollback targets specifically?
8. A scanning tool flags hundreds of findings in a widely-used base image, and the team has started ignoring the scanner's output entirely due to alert fatigue — how do you redesign the scanning and triage process to separate genuinely exploitable findings from noise?
9. An emergency exception to signature verification enforcement is granted during an incident to allow an unsigned image to deploy, and this exception is never revoked, remaining active for months — how do you build exception-lifecycle management for security controls like this?
10. A build's provenance attestation is generated correctly, but a downstream verification step only checks that a signature exists, not that it was issued by an identity your organization actually trusts — how do you close this verification gap?
11. Docker image caching in your CI pipeline causes a build to use a stale cached layer containing an outdated dependency, even after the Dockerfile was updated to bump that dependency's version — how do you diagnose and fix this class of stale-cache bug?
12. A container's resource limits are set based on typical usage, but a memory leak in the application causes it to hit the limit and get OOM-killed repeatedly, and the restart loop masks the underlying leak from casual monitoring — how do you build detection that surfaces the real problem here?
13. Gitleaks is integrated into your CI pipeline for secret detection, but a secret embedded in a binary artifact rather than source text passes through undetected and reaches a public registry — how do you extend scan coverage to catch this class of gap?
14. A vulnerability's severity score from a scanner is "critical," but the actual exploitability in your specific deployment context is very low because the vulnerable code path is never reached — how do you build a triage process that accounts for this without simply ignoring critical findings by default?
15. A registry's replication to a secondary region lags significantly behind the primary, and a deployment pulling from the secondary during a regional failover gets an older image than intended — how do you validate replication freshness before depending on it during a failover?
16. Remediation ownership for a vulnerability found in a shared base image used by 40 services is unclear, and the finding sits open for months because no single team feels responsible for the fix — how do you assign ownership for shared-dependency vulnerabilities?
17. A build-once, promote-immutable pipeline is supposed to guarantee the same artifact moves through every environment, but a hotfix process for production bypasses this by rebuilding directly against the production branch, breaking the provenance chain — how do you close this bypass path?
18. An exploitability-based triage process deprioritizes a vulnerability because the vulnerable function isn't called in normal operation, but an attacker later finds an indirect path to trigger it — how do you build triage that accounts for this kind of missed indirect exploitability?
19. A key used for container image signing is suspected to be compromised, and you need to revoke trust in every image signed with it without halting all deployments — how do you plan for key-compromise recovery in advance rather than improvising during the incident?
20. Static analysis and SCA tools both run in CI but report overlapping findings using different identifiers for the same underlying vulnerability, making it hard to track whether a specific issue has actually been remediated — how do you build a unified view of remediation status across tools like this?

14. 15. 16. A VerticalPodAutoscaler's recommendation mode suggests significantly higher resource requests than current usage justifies, based on a brief historical spike, and applying it would meaningfully increase cluster cost — how do you validate VPA recommendations before trusting them?
17. A Crossplane composition used for self-service database provisioning has a claim that succeeds but silently provisions the database in the wrong region due to a default value in the composition that wasn't overridden — how do you build validation into a platform API to catch this before it reaches production?
18. A control-plane failure in a service mesh (Istio/Linkerd) doesn't immediately affect data-plane traffic due to cached configuration, but a subsequent pod restart picks up a stale or missing configuration and starts failing — how do you design for graceful degradation when the mesh control plane is unavailable?
19. Cluster Autoscaler refuses to scale down a node because a single pod without a proper disruption budget or termination handling is preventing eviction, and this quietly costs the team money for weeks — how do you find and fix nodes that are stuck this way?
20. A Backstage software catalog shows a service as owned by a team that no longer exists after a reorg, and during an incident, nobody can quickly find who actually owns the service now — how do you keep catalog ownership metadata from silently going stale?
21. An admission webhook (Gatekeeper/Kyverno) adds meaningful latency to every pod creation in the cluster, and during a traffic spike requiring rapid pod scale-up, this latency becomes a bottleneck in itself — how do you validate that policy enforcement doesn't become a scaling bottleneck?
22. A Helm chart's secrets are passed as plain values in a values file that's checked into Git, and this isn't caught until a security review months later — how do you audit Helm-based deployments for this kind of secret-handling gap at scale?
23. A namespace intended for strict multi-tenant isolation shares a node pool with other tenants, and a noisy-neighbor workload in one namespace causes resource pressure that affects an unrelated tenant's pods — how do you diagnose and design against this kind of cross-tenant interference?
24. 25. A workload identity integration for a platform API (Crossplane) grants a claim's underlying cloud resources more permissions than the claim's declared intent, because the underlying composition's service account was provisioned with a broader default role — how do you validate that self-service provisioning doesn't silently grant excess privilege?

## Topic 6: Operating Systems, Proxies, And Network Runtime

2. An NGINX configuration reload triggered by a certificate rotation causes a brief spike in connection errors because in-flight connections are dropped instead of drained gracefully — how do you design config reloads to avoid this kind of disruption?
3. A retry policy with fixed-interval retries (no jitter) across many client instances causes a "thundering herd" of simultaneous retries against a recovering downstream service, extending an outage that would have otherwise self-resolved — how do you redesign retry behavior to prevent this?
4. A connection pool sized for average load is exhausted during a traffic spike, and requests start queueing with no timeout, causing a slow, cascading backup all the way up the call chain — how do you size and bound this pool to fail fast instead?
5. An Envoy circuit breaker trips correctly during a downstream outage, but nobody configured a fallback behavior, so the circuit breaker itself becomes the source of user-facing errors even after the downstream recovers — how do you validate circuit-breaker configuration end-to-end, not just the tripping behavior?
6. A Linux filesystem runs out of inodes rather than disk space, causing write failures that standard disk-usage monitoring doesn't catch because free space still looks healthy — how do you build monitoring that would catch this?
7. A WAF rule update meant to block a specific attack pattern also blocks a legitimate API client whose request bodies happen to match the pattern, and this isn't discovered until that client's error rate spikes — how do you validate WAF rule changes before they affect production traffic?
8. Retry amplification occurs when a client retries a request that itself triggers three downstream calls, and each of those downstream calls also has its own retry logic, multiplying load on a struggling service by an order of magnitude during an incident — how do you design retry budgets to prevent this?
9. An HAProxy health check considers a backend healthy based only on TCP connectivity, not actual application-layer responsiveness, and a backend that's technically listening but not processing requests correctly keeps receiving traffic — how do you design health checks that catch this?
10. A systemd service is configured to restart on failure with no backoff, and a persistent misconfiguration causes it to crash-loop hundreds of times per hour, flooding logs and consuming resources — how do you design restart policy to avoid this while still recovering from transient failures?
11. An API gateway enforces rate limiting per client IP, but a large enterprise customer's traffic comes from behind a shared NAT gateway, and legitimate requests from many of their users get rate-limited together as if from one client — how do you redesign rate limiting to handle this?
12. A private service endpoint is configured correctly, but a DNS resolution issue means some clients still resolve to the public endpoint instead, bypassing the private path entirely without any error being raised — how do you audit for this kind of silent bypass?
13. A deadline (timeout) set on a client call is shorter than the p99 latency of the downstream service it's calling, causing timeouts on a meaningful fraction of otherwise-successful requests — how do you set deadlines that are informed by actual downstream latency behavior rather than a guess?
14. A Linux kernel limit on open file descriptors is hit by a process handling many concurrent connections, causing new connections to fail silently while existing ones continue working, masking the severity of the issue — how do you build detection for this kind of resource-limit exhaustion?
15. An mTLS configuration between a proxy and backend services is correctly enforced for new connections, but long-lived connections established before a certificate rotation continue using the old certificate until they're eventually recycled — how do you handle certificate rotation for long-lived connections?
16. A DDoS protection service correctly absorbs a volumetric attack, but a smaller, application-layer attack that mimics legitimate traffic patterns slips through and degrades a specific backend service — how do you build layered protection that catches both attack types?
17. Idempotency isn't enforced on a specific API endpoint, and a client's retry logic (triggered by a timeout, not an actual failure) causes a duplicate transaction to be processed — how do you design this endpoint to make retries safe?
18. An egress gateway enforces a strict allowlist of external destinations, but a legitimate third-party API the application depends on rotates its IP ranges without notice, causing egress to silently start failing — how do you design egress control that's resilient to this kind of upstream change?
19. Disk I/O on a database host degrades gradually over weeks due to filesystem fragmentation, and query latency creeps up slowly enough that no single alert threshold catches it until it's a significant production problem — how do you build monitoring that catches this kind of slow-drift degradation?
20. Overload control on a service under extreme load starts shedding load correctly, but the shedding logic doesn't distinguish between request priority, and critical health-check traffic gets shed along with everything else, causing the service to be marked unhealthy and removed from rotation — how do you design load shedding to avoid this self-inflicted failure?

7. 8. A Kafka topic's retention period is shorter than the time it takes a downstream consumer to recover from an extended outage, and by the time the consumer comes back online, the messages it needed to process have already been deleted — how do you design retention to account for realistic consumer recovery time?
9. A RabbitMQ cluster's quorum queue loses its leader during a node failure, and a brief period of unavailability occurs while a new leader is elected, causing a burst of publish failures that the application doesn't retry correctly — how do you handle this transition gracefully at the application layer?
10. A Redis Sentinel-managed failover promotes a replica to primary, but the replica had a few seconds of replication lag at the moment of failover, so a handful of recently-written keys are silently lost — how do you quantify and communicate this data-loss tradeoff to stakeholders who assumed Redis failover was lossless?
11. A MySQL replica falls behind the primary during a bulk data load, and an application reading from the replica for a "read your own writes" flow serves stale data to users who just made a change — how do you redesign this flow to avoid serving stale reads?
12. A Cassandra repair process wasn't run on schedule for several weeks, and a node replacement during this window surfaces data inconsistency because hinted handoff couldn't fully cover the gap — how do you build monitoring to catch missed repair cycles before they become a consistency risk?
13.
